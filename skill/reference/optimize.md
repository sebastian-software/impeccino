# Optimize

Diagnose and improve the requested UI performance problem.

Establish the slow task, relevant environment, and comparable baseline before
changing code. Use measured traces, project tools, and suitable performance
knowledge to find the actual bottleneck. Optimize its owner rather than applying
framework recipes indiscriminately. Preserve behavior, visual identity, content,
accessibility, and support policy. Repeat the relevant measurement under the
same conditions and report observed differences, method, and limitations.
An unmeasured hypothesis is not a performance improvement claim.

Apply [craft-floor.md](craft-floor.md) before implementation. Use the resolved
target and existing answers; ask only about material gaps through the host's
structured question tool when available. These contracts follow
the host’s authorization, questions, delegation, and verification budget.
