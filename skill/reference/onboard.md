# Onboard

Improve the requested first-use path, empty state, or activation flow.

Identify the real first useful outcome, user context, existing knowledge, and
reachable states. Use actual product behavior and content. Preserve expert
access and already completed work; do not turn a focused empty-state task into
a compulsory tour. Select suitable journey, copy, and state knowledge.
Verify entry, progress, completion, skip or dismissal where supported, permissions,
errors, return visits, and accessibility. Report the outcome the implemented
flow enables without inventing engagement or conversion results.

Apply [craft-floor.md](craft-floor.md) before implementation. Use the resolved
target and existing answers; ask only about material gaps through the host's
structured question tool when available. These contracts follow
the host’s authorization, questions, delegation, and verification budget.
