# Extract

Extract genuinely reused tokens or components into the project’s design system.

Find the current source of truth and owning app boundary. Use existing system
conventions; resolve a material destination ambiguity before creating another
system. Identify actual reuse, common behavior, and variant differences.
Extract a focused primitive, update its consumers, and preserve their appearance,
semantics, states, and APIs. Avoid abstracting one-off similarities into a new
framework. Verify affected consumers and document durable system decisions
through document.md when the requested scope includes the system record.

Apply [craft-floor.md](craft-floor.md) before implementation. Use the resolved
target and existing answers; ask only about material gaps through the host's
structured question tool when available. These contracts follow
the host’s authorization, questions, delegation, and verification budget.
