# Craft floor

Read this after direction is settled and before a UI edit. Apply the user's
request, product truth, incumbent system, and agreed scope. Select suitable
design knowledge for the task from what the host has available; no external
skill or catalogue is required to complete the work.

## Interpret the evidence

Detector output contains measurements and pattern warnings. Establish the
affected role and rendered consequence before treating a finding as a defect.
Fix broken behavior, inaccessible paths, misleading claims, and unreadable or
hidden content. A deliberate style does not excuse those failures.

Style warnings are context-dependent. Preserve a choice justified by the brief,
content, task, or accepted system. Functional section labels, nested actionable
entities, coherent radii, readable grey text, well-made SVG, and purposeful image
hover can all be valid. Do not turn a font, palette, effect, file format, or
model's habits into an absolute prohibition.

When several unexamined choices create an interchangeable page, change the
owning hierarchy, content, media, or interaction decision. Explain what product
relationship is missing; swapping one fashionable preset for another is not a
resolution. Existing detector waivers remain the user's recorded decisions.

## Verify the changed result

Use the bounded inspection rounds in SKILL.md and the active playbook. Reuse
hook findings rather than running a duplicate source scan. Inspect the affected
reading or task path with real content and relevant sizes, states, and input
methods; include contrast, focus, source order, overflow, and reduced motion
where the change can affect them. A clean scan does not prove quality.

Report remaining findings with evidence, consequence, and an appropriate
change. Distinguish an accepted exception from an unverified assumption, and
stop when the requested outcome and required checks pass.
